# 大分類17区分の重複・境界監査

更新日：2026-11-03  
状態：分類案の構造監査。最終採用前の設計判断を記録する。

## 監査結論

**大分類17区分は現段階では維持し、分類数の削減は行わない。** 17区分の多くは利用者がタグを探す際の異なる入口になっており、無理に統合すると検索性が落ちる。一方で、現行案には境界の重複・名称の曖昧さがあるため、小分類と判定ルールを整える必要がある。

カテゴリは「タグが何を表しているか」で1つだけ決める。成人向けレーティング、Positive / Negative、確認状況、出典などはカテゴリに混ぜず、横断属性として扱う。色語は属性としても保持しない。色だけが修飾している複合語は基本語へ正規化し、意味が変わる既成語等だけ原形維持候補とする。

## 特に混同しやすい境界の判定ルール

### 人数・被写体構成 / 構図・カメラ
- `two girls`：人数・被写体構成
- `group of people`：人数・被写体構成
- `upper body`：構図・カメラ
- `from above`：構図・カメラ
- `left side of frame`：構図・カメラ

### 人物の特徴 / 顔・表情 / 髪・頭部
- 身体属性・体型・肌・一般的な種族：人物の特徴
- 目・口・鼻・視線・表情：顔・表情
- 髪型・前髪・髪質・頭部装飾：髪・頭部
- 同じタグを複数カテゴリへ重複登録しない。複合語は中心となる描写対象で判断する。

### 服装・装飾 / 家具・設備・物品
- 身につけている衣服・アクセサリー：服装・装飾
- 手に持つ道具・武器：家具・設備・物品
- 身体に装着する防具：服装・装飾
- 置かれた家具・道具：家具・設備・物品

### ポーズ・動作 / シチュエーション・関係性
- 身体がどう動いているか：ポーズ・動作
- 誰とどのような関係か、どのような場面か：シチュエーション・関係性
- 接触を伴う動作タグは、動作そのものが中心ならポーズ・動作。関係性や場面を表す語ならシチュエーション。

### 背景・場所 / 家具・設備・物品 / 乗り物
- 空間・建物・自然環境：背景・場所
- 空間内の個別物体：家具・設備・物品
- 実際の車両・乗り物：乗り物
- 車両の模型・玩具・ミニチュア：家具・設備・物品

### 画風・描写 / 光・演出 / 品質・ネガティブ
- 何で・どのように描かれているか：画風・描写
- どのような光や画面効果があるか：光・演出
- 仕上がりの品質評価、破綻、不要要素の除外：品質・ネガティブ
- Negative指定はカテゴリとは独立した出力属性で管理する。

### 人物の特徴 / 生物・動植物 / キャラクター・作品
- 固有のキャラクター・作品名：キャラクター・作品
- 一般的な人間型種族・職業・役割：人物の特徴
- 独立した動物・植物・生物種：生物・動植物
- 擬人化・獣人などは、人物描写として使われているか、生物そのものを指すかを確認して分類する。

## 推奨する実装ルール

1. 各タグは `categoryId` を必ず1つだけ持つ。
2. `subcategoryId` は任意。小分類が未定義・不要なタグには `null` を許容する。
3. カテゴリ定義に `order` を持たせ、UI表示順とプロンプト出力順を同じ定義から取得する。
4. `promptTarget` は `positive | negative | both | none` のいずれか。意味カテゴリとは独立。
5. `rating` は成人向け表示制御の属性。カテゴリとは独立。
6. `reviewStatus` は `verified | provisional | needs_review` を基本候補とし、未確認データを確定扱いしない。
7. 同義語は正規タグの `aliases` に集約し、別の出力タグとして重複させない。
8. 上位・下位・関連語は同義語とは別の関係データで表現する。
9. 色語だけが修飾しているタグは基本語へ正規化する。色属性や色別派生タグを新スキーマに作らない。
10. 意味が変わる既成語・固有名詞・食品名・動植物名・模様名・素材名などは原形維持候補として個別確認する。

## 次の設計段階で決めること

- 17大分類の表示名（日本語・英語）と安定ID。
- 小分類の採用範囲。小分類を過剰に増やさず、実際にタグが一定数集まる単位を優先する。
- `rating` の値と、一般表示での成人向け語彙の初期非表示ルール。
- `promptTarget` の初期値と、Positive / Negative双方に出すケースの扱い。
- `reviewStatus` の更新・承認手順。
- IDの生成規則、タグ名変更時の互換性、別名・廃止タグの扱い。

この監査は17区分を最終承認したものではない。現段階では17区分を維持する推奨案とし、次に小分類・フィールド定義を具体化する。

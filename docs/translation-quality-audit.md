# 翻訳品質監査

## 実行

```sh
node scripts/audit-translations.mjs --write
node scripts/audit-translations.mjs
node --test tests/audit-translations.test.mjs
```

`--write` は `data/translation-audit-candidates.json` だけを再生成します。`data/tags.json` と `data/tag-review.json` は変更しません。引数なしでは既存レポートとの差分を検査します。

## 候補の読み方

- `high`: 既知の誤訳ペアに完全一致した項目。修正優先度の高い候補ですが、最終的な訳語決定には文脈確認が必要です。
- `medium`: 空欄、同一訳、疑わしい混在表現など。文脈を確認してください。
- `low`: 主に英語残存。作品名・キャラクター名・作者名・ブランド名・型番など、正当な英語表記を含む可能性があります。

検出理由は複数付与されるため、理由別件数の合計は候補総数と一致しません。英語残存だけで誤訳と断定しません。

## レビュー状態

候補の `status` は `data/tag-review.json` の `translationStatus` を読み取ります。台帳にないタグは `unreviewed` と表示します。監査スクリプトはレビュー状態を変更せず、`verified` への昇格も行いません。翻訳状態と分類状態は別管理です。

## 限界

この仕組みは既知パターンと文字種・表記の検出です。意味理解による全件校正ではなく、候補外にも誤訳が残り得ます。固有名詞・短い略称・作者名などは、出典や文脈を確認して人手で判断してください。分類品質はこの監査の対象外です。

# 旧データ整理監査（初回）

監査対象: `main` の現行データ  
作業ブランチ: `cleanup/legacy-data-audit`  
目的: 旧データを無条件に維持せず、不要なデータを削除・統合できるように実態と依存関係を分離して記録する。

## 実測結果

| 項目 | 件数 | 判断 |
|---|---:|---|
| タグ本体 | 10,988 | 全件維持を前提にしない |
| 正規化前の完全重複タグ | 0 | 重複削除対象なし |
| 日本語欄空欄 | 0 | 訳の品質は別途監査 |
| 英語表記と日本語表記が同一 | 42 | 固有名詞・製品名等を含むため一括削除不可 |
| 数字だけのタグ | 1 | `69`。意味のあるタグなので削除しない |
| 記号だけのタグ | 12 | 目・表情・効果表現を含むため一括削除しない |
| 旧分類「未分類」 | 3,318 | 最優先の整理対象 |
| 分類候補ファイルの provisional | 976 | 既存タグとの重複を解消し、不要な候補台帳を整理する |
| 分類候補ファイルの needs_review | 2,343 | 未確定データ。重複・陳腐化を監査して整理する |

## アプリが直接読むデータ

- `data/tag-groups.json`

- `data/tag-taxonomy.json`

管理画面の `src/admin.js` も別途依存関係を確認してから、管理用sidecarを整理する。

## 初回に安全に削除できる不要物

以下の3ファイルは内容がすべて `temporary` の9バイトの一時ファイルであり、アプリ参照・ドキュメント用途がないことを確認した。

- `docs/full-tag-retranslation-policy.md.tmp`
- `docs/implementation-backlog.md.tmp`
- `docs/tag-reclassification-audit.md.tmp`

## 次の整理方針

1. 3,318件の未分類タグを、採用・統合・削除・要確認に分ける。曖昧な固有名詞は削除せず保留する。
2. 703件の新分類レビュー候補は、既存タグを重複追加せず、既存レコードの更新候補として扱う。
3. 旧分類候補976件と要確認2,343件を新しい分類体系に照合し、重複・競合・未使用の候補データを削る。
4. 監査途中のJSON/JSONLは、最終成果物に必要なものだけ残す。履歴・根拠として必要なものはアーカイブにまとめる。
5. アプリと管理画面の参照を新しい正規データへ移行し、テストを通した後に旧sidecarを削除する。

## 削除の原則

- 削除対象・理由・元データを監査レポートに残す。
- 既存タグの完全重複がないため、タグ数を減らす作業は意味・用途を確認したうえで行う。
- ファイルを削除する前に、通常画面・管理画面・テスト・CIからの参照がないことを確認する。
- 本監査はmainを変更しない。削除はこの作業ブランチ上で差分を確認しながら行う。

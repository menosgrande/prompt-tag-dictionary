## 次の整理方針

1. 3,318件の未分類タグを、採用・統合・削除・要確認に分ける。曖昧な固有名詞は削除せず保留する。
2. 703件の新分類レビュー候補は、既存タグを重複追加せず、既存レコードの更新候補として扱う。
3. 旧分類候補976件と要確認2,343件を新しい分類体系に照合し、重複・競合・未使用の候補データを削る。
4. 監査途中のJSON/JSONLは、最終成果物に必要なものだけ残す。履歴・根拠として必要なものはアーカイブにまとめる。
5. アプリと管理画面の参照を新しい正規データへ移行し、テストを通した後に旧sidecarを削除する。

## 削除の原則

- 削除対象・理由・元データを監査レポートに残す。
- 既存タグの完全重複がないため、タグ数を減らす作業は意味・用途を確認したうえで行う。
- ファイルを削除する前に、通常画面・管理画面・テスト・CIからの参照がないことを確認する。
- 本監査はmainを変更しない。削除はこの作業ブランチ上で差分を確認しながら行う。

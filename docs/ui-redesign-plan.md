# UI改善計画：カタログ型タグ辞書

## 目的

約1.1万件のプロンプトタグを「探す → 選ぶ → 出力する」流れで扱いやすくする。既存アプリを作り直すのではなく、現在の静的構成・データ形式・保存機能を維持して、小さな差分で改善する。

## 参考にする考え方

- Eagle：素材カタログのような一覧性と、画像がある項目の視覚的プレビュー。
- BoardGameGeek：カテゴリ、分類状態、確認状態など複数条件を組み合わせる絞り込み。
- Notion：データ項目と分類・並べ替えの一貫性。
- この辞書独自：選択したタグからプロンプトを組み立て、コピーまたはTXT保存する。

参考サイトの見た目をそのまま再現することは目的にしない。タグ選択とプロンプト出力の効率を優先する。

## 変更しない前提

- GitHub Pagesで動く静的ブラウザアプリを維持し、サーバー・ログイン・外部API・ビルド工程を追加しない。
- 同梱タグデータ、インポート、カスタムタグ、localStorage、プリセット、タグ選択、出力・コピー・TXT保存を維持する。
- 1.1万件すべてを一度にDOM描画せず、100件ページ送りを維持する。
- UI改修に便乗してタグの翻訳・分類を一括修正しない。
- UIの差分とデータ修正を同じ変更に混ぜない。

## Phase 1：検索・絞り込み・一覧

### 今回の作業

- 分類状態（すべて／分類済み／未分類）と、確認状態（すべて／未評価／要確認あり／タグの👎／訳の👎／分類の👎）を独立させる。
- 検索語・カテゴリ・分類状態・確認状態をAND条件で適用する。
- フィルター変更時はページを先頭に戻し、件数と表示範囲を更新する。
- 既存の並べ替え、カテゴリ階層、評価、選択タグ、出力を維持する。
- 変更範囲は原則として index.html、src/app.js、styles.css に限定する。

### 既存動作との互換性

- 「要確認あり」は既存の意味を維持する。タグ／訳／分類の👎、未分類、訳なしのいずれかを含む項目を対象にする。
- 「未評価のみ」はタグ・訳・分類のすべてに評価が付いていない項目を対象にする。
- 👎は確認が必要という印であり、自動修正や他ユーザーとの共有を意味しない。

## Phase 2：画像プレビュー

- 既存データにプレビュー情報が存在するタグだけを対象にする。
- PCではホバー／キーボードフォーカス、スマートフォンではタップで確認できるようにする。
- 画像は必要時に読み込み、画像がない項目には空の枠やダミー画像を表示しない。
- 画像の収集、ライセンス確認、大量の画像URL追加は別作業にする。

## Phase 3：必要性を見て追加

- 要確認項目を先頭にする並べ替え。
- プレビュー画像があるタグに限定するフィルター。
- 保存済みタグセットなど、利用状況から必要性が確認できた機能。

Phase 2・3をPhase 1に先回りして一括実装しない。

## GitHubでの変更手順

1. 機能ごとに作業ブランチを作る。
2. 変更差分を小さく保ち、PRで変更目的・影響範囲・確認結果を記録する。
3. まずJavaScript構文、タグデータ監査、HTMLのID重複・参照漏れを確認する。
4. その後、ブラウザで検索・複合フィルター・ページ送り・選択・評価・コピー・TXT保存を確認する。
5. 390px幅のスマートフォンとPCの両方で表示を確認し、未確認項目を明記してからmainへ反映する。

コードを読んだだけでブラウザ動作確認済みと報告しない。確認できない項目は「未確認」と記録する。

## Phase 1の受け入れ条件

- 分類状態と確認状態を同時に指定でき、両方の条件を満たすタグだけが表示される。
- 日本語・英語検索、カテゴリ選択と併用できる。
- フィルター変更時にページが先頭へ戻り、件数・表示範囲が正しい。
- 絞り込みやページ移動の後も選択済みタグが失われない。
- タグ／訳／分類の評価をそれぞれ付け外しでき、他の評価に影響しない。
- 既存のインポート、カスタムタグ、プリセット、出力、コピー、TXT保存が維持される。
- 初期データの件数、重複、分類値、翻訳内容がUI変更によって変化しない。
- JavaScript構文チェックとデータ監査が通る。
- ブラウザ未確認の項目は、確認済みとして扱わない。
